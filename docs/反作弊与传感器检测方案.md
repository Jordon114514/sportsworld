# 第一部分：反作弊检测方案

## 架构总览

四层防御，客户端只做「初筛」，真正的裁决在服务端。

```
① 单点实时校验 (native)      isValidPoint()      每来一个 GPS 点即算分
② 五点打卡校验 (Java)        FivePointPlugin     要求恰好 5 个点，25 米内
③ 数据全量上报 (Java)        UploadFormatEntity  10 秒粒度原始数据回传
④ 服务端复检 + 人脸          RunFaceCheck        按配置随机抽检
```

### 判定式

```c

     && param_7 != 0                  // GPS 有效
     && (distance + sat + type + speed) > 0x41;   // 总分 > 65
```

满分 100，及格线 **65 分**。

> `param_8` 来自 `OoooO0(sWLatLng)`（`OooOOO0.java:861`）：
>
> ```java
> public final boolean OoooO0(SWLatLng cur) {
>     SWLatLng prev = this.f26107OooOo0o;
>     return prev != null
>         && prev.OooO0OO() == cur.OooO0OO()      // 经度相同
>         && prev.OooO0Oo() == cur.OooO0Oo();     // 纬度相同

>
> 含义是**「本点与上一点坐标完全相同」**。判定要求它 `== 0`，即坐标必须发生变化。
> 这是防「原地不动刷里程」的硬性条件——坐标完全没动的点直接判负。

# 附：完整判定链

```
GPS 点到达
  ↓
isValidPoint(sat, speed, type, dist, hasGps, 坐标未变化?)
  ├─ 坐标与上点完全相同 → param_8=1 → 直接判负
  ├─ 总分 ≤ 65          → 该点作废（Oooo0OO()，type=-1）
  └─ 通过               → 计入轨迹
  ↓
FivePointPlugin.getPointType(latLng)
  ├─ 五点数量 != 5      → "五个点错误"，本轮作废
  ├─ 距离 ≤ 25m         → 命中，setIsPass(true)，移出列表
  └─ 未命中             → 继续
  ↓
每 10 秒落库 StepsPerTenSec + SpeedPerTenSec（多源取 min，单次 ≤ 8 步）
  ↓
RunSportUploadManger 组装 UploadFormatEntity
  ├─ allLocJson + fivePointJson + steps/speed 序列
  ├─ signRunRecord() 签名
  └─ faceCheck + geeToken
  ↓
服务端复检（重算轨迹、步频-速度相关性、人脸结论）
```
