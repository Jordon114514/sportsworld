## 五、为什么整体编译不出 class

即使把 8,484 个候选一起交给 javac，`.class` 输出仍为 0。原因已定位：

1. **javac 遇到语法错误会中止整个编译单元**，不产出任何 class
2. 迭代 11 轮排除 320 个语法错误文件后，仍有新的错误文件被 `-sourcepath` 隐式拉入
3. 只保留 16 个错误文件的批次，javac 依然整体中止

**这不是源码质量问题，是 javac 的行为特性**：一个 `.java` 有语法错误，同批次全部不产出。

验证方式改为**单文件编译**后立即成功（70/120），证明源码本身是可编译的。

## 六、不可修复的固有缺陷

以下两类**在 Java 源码层面无法修复**，属于 jadx 的架构限制：

### 6.1 枚举常量带类体（88 个文件）

jadx 输出：

```java
public final enum SortedLists$KeyPresentBehavior$2 extends SortedLists.KeyPresentBehavior {
    public SortedLists$KeyPresentBehavior$2(String str, int i) {
        super(str, i, (SortedLists.OooO00o) null);
    }
}
```

Java 语言**禁止枚举继承枚举**，正确写法应是：

```java
public enum KeyPresentBehavior {
    PRESENT_PRESENT {
        @Override public <E> int resultIndex(...) { ... }
    };
}
```

jadx 无法自动内联回父枚举，只能拆成非法文件。
**业务包 0 个，全部在 `com.google.common.*`。**

### 6.2 Kotlin 内联 lambda 伪语法（84 处）

```java
NativeHostActionChannel.performGoSportOutdoorRun.2.1.OooO0O0(this.xxx, ...);
```

`方法名.2.1.类名` 不是合法 Java。这是 jadx 无法解析 Kotlin inline 展开后的匿名类归属时生成的占位语法。

若目标是得到**可编译工程**，按以下顺序处理：

```bash

#    - kotlin-stdlib.jar -> 覆盖 13.4%
#    - 第三方 aar/jar    -> 覆盖 4.2%

# 3. 修复 229 个业务缺陷文件

javac -implicit:none -cp "android.jar:kotlin-stdlib.jar" <单个.java>
```
