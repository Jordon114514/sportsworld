## 二、加固结构完全破解

### 2.1 载荷格式真相

`classes.dex` 尾部 68.16 MB 并非「整体加密」，而是 **8 个完整 DEX 单元顺序拼接**，壳只做了两件事：

1. 抹掉每个单元开头的 **112 字节 DEX 头**
2. 每个单元删除 **996 个 string_ids 项**（996×4 = 0xF90 字节）

因此每个单元内的所有相对偏移都整体前移了 `0xF90`。这不是加密，是**结构位移**——所以用标准 DEX 解析器会全部失败。

### 2.2 破解方法

关键推导链：

```
map_list 中 string_ids 声明 size=82606
实测单调递增表只有 81610 项
差额 996，而 996×4 = 0xF90
→ 所有后续段偏移 = map 声明值 - 0xF90
→ 真实单元起点 = 表面起点 - 0xF90
```

验证：用 `base-0xF90` 作为起点，map_list 全部 18 个段**完全连续自洽**：

```
string_ids  0x70      + 82606×4  = 0x50B28  ✓ = map 的 type_ids 偏移
type_ids    0x50B28   + 10472×4  = 0x5AEC8  ✓ = map 的 proto_ids 偏移
proto_ids   0x5AEC8   + 16042×12 = 0x89EC0  ✓ = map 的 field_ids 偏移
field_ids   0x89EC0   + 58211×8  = 0xFB9D8  ✓ = map 的 method_ids 偏移
method_ids  0xFB9D8   + 65526×8  = 0x17B988 ✓ = map 的 class_defs 偏移
```

八个单元全部通过该校验（`sections_contiguous=True`）。

## 四、反作弊算法（完整还原）

`isValidPoint(int, float, int, float, boolean, boolean)` 反编译结果是一个**加权评分制**：

```c
// param_6: 整数参数（很可能是卫星数/定位精度）
if (param_6 < 3)       iVar1 = 0;
else if (param_6 < 5)  iVar1 = 5;
else if (param_6 < 8)  iVar1 = 15;
else                   iVar1 = (param_6 > 14) ? 30 : 25;

// param_5: 运动类型 (1=跑步? 2=?)
iVar2 = (param_5 == 1) ? 30 : (param_5 == 2 ? 20 : 15);

// param_2: 速度/配速
if (param_2 >= 10.0) {
    if (param_2 >= 50.0f)   iVar3 = (param_2 >= 100.0f) ? 0 : 10;
    else                    iVar3 = 20;
} else                      iVar3 = 30;

// param_1: 距离/位移
iVar4 = (param_1 <= 0.0) ? 0 : 10;

// 最终判定
return param_8 == 0 && (param_7 != 0) && (iVar4 + iVar1 + iVar2 + iVar3 > 0x41);  // > 65
```

两个阈值已从 `.rodata` 实际读取：

| 地址 | 字节 | 浮点值 |
|---|---|---|
| `0x1737b0` | `00 00 48 42` | **50.0** |
| `0x1737b4` | `00 00 c8 42` | **100.0** |

即：速度 ≥10 得 30 分；≥10 且 <50 得 20 分；≥50 且 <100 得 10 分；≥100 得 0 分（明显异常速度）。

**满分模型**：卫星/精度 30 + 运动类型 30 + 速度 30 + 距离 10 = 100；判定线 65 分。

**判定逻辑总结**：四个维度加权，总分 > 65 且 `param_7 != 0`、`param_8 == 0` 才算合法轨迹点。这是客户端一侧的反作弊校验，服务端还有独立校验。

## 十、结论

本版**完成了完整的静态脱壳**。核心发现是：网易易盾对这个 APK 并未做真正的加密，而是做了**结构位移**（抹头 + 删 996 个字符串索引），只要有 `map_list` 就能精确还原。

这是加固实现的**结构性弱点**：`map_list` 保留了原始布局信息，而壳只是挪动了数据，导致偏移差恒定为 `0xF90`。一旦识别出这个常量，8 个单元同时告破，无需任何动态 hook、无需运行时。

配合 adb root 的内存取证，形成了静态还原 + 动态验证的双重证据链。

## 十一、加固实现的结构性弱点（技术总结）

网易易盾在本样本中使用的是「**抹头 + 索引裁剪**」而非真加密：

1. 抹掉每个 DEX 前 112 字节头 → 标准解析器看到的是垃圾
2. 删除每单元 996 个 string_ids 项 → 所有内部偏移整体前移 `0xF90`
3. **但 `map_list` 原封不动保留了原始布局**

因此只要有 `map_list`，就能反推出恒定位移量 `0xF90`，8 个单元一次性全部还原。这类加固的本质是**混淆而非密码学保护**——数据本身是明文，只是被挪了位置。这也解释了为什么内存里能直接 dump 出 `dex\n035` 头：壳在加载时只是把数据搬回原位。

对比真正的加密加固（载荷高熵、无法静态还原），本样本的防护强度明显偏低。
